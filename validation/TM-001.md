# Qaabil traceability matrix v1

TM-001, Rev A (draft), October 2026. Built from SRS-001, RA-001, DS-001, TC-001, and TC-002, all at Rev A. Items in \[brackets\] are open.

## Purpose

This document links every requirement of Qaabil version 1 to the risks it controls, the design section that implements it, and the test cases that verify it. It shows at a glance that nothing is specified without being tested, and that nothing is tested without a reason. Release is blocked if any requirement lacks a test, a risk link, or a design section, as set out in the validation plan.

## How to read the matrix

- **R** is the requirement's provisional risk level from SRS-001.

- **Risks** lists the risk IDs in RA-001 where the requirement is named as a control.

- **Design** uses these short names for the sections of DS-001:

| Short name | DS-001 section                    |
|------------|-----------------------------------|
| Separation | Company separation and routing    |
| Auth       | Authentication and access control |
| Signatures | Electronic signatures             |
| Audit      | Audit trail                       |
| Workflow   | Complaint and CAPA workflow       |
| Email      | Email intake                      |
| Agent      | Triage agent design               |
| Data       | Data model                        |
| Export     | Export                            |
| Security   | Security controls                 |
| Backup     | Backup and recovery               |
| Release    | Environments and release          |
| Tech       | Technology choices                |
| Front end | Front end |
| Availability | Availability |

- **Tests** lists test case IDs from TC-001 and TC-002. Results are not yet recorded, and every case is not yet run. A results column will be added when testing starts.

## Findings

- **Risk links were missing for 30 requirements.** Functional requirements such as numbering, links, search, and export were not named as controls in RA-001. RA-001 now has RSK-028 for core record-keeping failures, and extra control links were added to existing risks.

- **Tests covering several requirements.** T-AGT-08 covers AGT-008, LIB-002, and LIB-003. T-AGT-14 covers AGT-014 and LNG-002. T-CMP-10 and T-AGT-02 both cover CMP-010. This is acceptable, but a failure in one of them must be recorded against every requirement it covers.

- **Proposed requirement ESG-006** from P11-001 (signature acknowledgement) is not in SRS-001, so it is not in this matrix.

## Maintenance

- Update this matrix whenever a requirement, risk, design section, or test case is added, changed, or removed, and increase the revision letter.

- Add result, defect, and evidence columns at the start of test execution, and keep the Rev A version as the pre-execution baseline.

- Consider generating the coverage check from the document IDs automatically, so that the table cannot drift from the source documents.
