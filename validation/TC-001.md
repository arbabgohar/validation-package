# Qaabil test cases core platform

TC-001, Rev A (draft), October 2026. Written against SRS-001, RA-001, DS-001, and TP-001, all at Rev A. Items in \[brackets\] are open.

## Purpose

This document lists the test cases that verify the core platform of Qaabil version 1 against its requirements: accounts, access, signatures, audit trail, complaints, email intake, NCRs, CAPA, products, rule sets, the reference library, entitlements, export, language, security, and operations. The triage agent has its own test cases in TC-002. Each case traces to requirements and risks, so the traceability matrix (TM-001) can show that every requirement is tested.

## How to use this document

- Test case IDs have the form T-GROUP-NN. Req lists the requirement IDs covered, and Risk lists the risk IDs from RA-001 that the case helps control.

- Results are recorded on a controlled execution copy of this document, with evidence references, pass or fail, tester, and date. Failures become defects and are never edited out.

- High-risk cases are run at every release. Medium and Low cases follow TP-001.

## Common preconditions

- Staging environment at the version under test, with versions recorded

- Three test companies (A, B, and C), each with an administrator, approver, contributor, and read-only auditor

- Synthetic data only, and a test identity provider tenant

- Rule sets loaded for the US and one synthetic second test market, used only to test multi-market logic, with known deadlines
